# أكاديمية لومينول

[English](README.md) · **العربية**

أكاديمية لومينول مؤسسة تعليمية ثلاثية اللغات (العربية والفرنسية والإنجليزية) مقرّها البليدة في الجزائر، وتضمّ ثلاث مدارس: **مدرسة علم النفس** و**مدرسة اللغات** و**مدرسة التطوير المهني**. يحتوي هذا المستودع على الشيفرة الإنتاجية الموحّدة (monorepo) للموقع العام، وبوابة المتعلّمين، ومساحة الإدارة وإدارة علاقات العملاء (CRM)، ونظام إدارة المحتوى التحريري.

| التطبيق       | الغرض                                                 | بيئة الإنتاج                              | التشغيل المحلي        |
| ------------- | ----------------------------------------------------- | ----------------------------------------- | --------------------- |
| `apps/web`    | الموقع العام: المدارس والبرامج والاستشارات            | https://luminol-academy-web.vercel.app    | http://localhost:3000 |
| `apps/admin`  | الإدارة وإدارة علاقات العملاء والعمليات والمالية      | https://luminol-academy-admin.vercel.app  | http://localhost:3001 |
| `apps/portal` | بوابة المتعلّمين والعملاء: الدورات والتقدّم والشهادات | https://luminol-academy-portal.vercel.app | http://localhost:3002 |
| `apps/studio` | Sanity Studio لإدارة المحتوى التحريري                 | مستضاف لدى Sanity                         | http://localhost:3333 |

## البدء

### المتطلبات

- Node.js بالإصدار 20.19 أو 22.13 أو 24 فما فوق
- pnpm بالإصدار 10.34.5 أو أحدث ضمن الإصدار الرئيسي 10 (فعّله عبر `corepack enable`)
- Docker Desktop لتشغيل PostgreSQL محليًا
- حسابات لدى Clerk وSanity وResend وVercel وAnthropic عند ربط الخدمات المستضافة

### الإعداد المحلي

<div dir="ltr">

```bash
corepack enable
pnpm install
cp .env.example .env                 # replace only the placeholders you need
docker compose up -d postgres        # PostgreSQL 16 with a health check
pnpm db:generate                     # generate the Prisma client
pnpm db:migrate --name init          # apply migrations to the local database
pnpm dev                             # start every application
```

</div>

يحتوي الملف `.env.example` على قيم آمنة للعرض فقط. لا تُضِف أبدًا ملف `.env` حقيقيًا إلى المستودع. جميع المتغيّرات موصوفة في [الإعداد والنشر](docs/ar/CONFIGURATION.md).

### GitHub Codespaces

1. افتح المستودع على GitHub واختر **Code ← Codespaces ← Create codespace** على الفرع الذي تريد مراجعته.
2. نفّذ أوامر الإعداد المحلي أعلاه في طرفية Codespaces.
3. افتح لوحة **Ports**؛ المنافذ 3000 و3001 و3002 و3333 تقابل التطبيقات الأربعة. أبقِ المنافذ خاصة ما لم تقصد مشاركة معاينة.

## بوابات الجودة

يشغّل كل طلب دمج سير العمل `quality`، وهو شرط إلزامي قبل الدمج في `main`:

1. تثبيت الاعتماديات بنسخة مجمّدة، وفحص الأسرار، والتحقق من تثبيت إصدارات Actions
2. توليد Prisma والتحقق من المخطط وإعادة تشغيل الترحيلات على PostgreSQL مؤقت
3. الفحص البرمجي، والتحقق من تنسيق Prettier، والفحص الصارم للأنواع، واختبارات الوحدات
4. البناء الإنتاجي لكل التطبيقات
5. اختبارات Playwright العامة، والمسارات الموثّقة عند توفّر حالتها المحمية
6. تدقيق اعتماديات الإنتاج (`pnpm audit --prod --audit-level high`)

الفرع `main` محمي: لا تصل إليه التغييرات إلا عبر طلبات الدمج، ويُمنع الدفع القسري والحذف.

## أعراف الهندسة

القواعد الكاملة في [AGENTS.md](AGENTS.md)، وباختصار:

- استخدم pnpm فقط ونفّذ أوامر مساحات العمل من جذر المستودع.
- حافظ على الوضع الصارم في TypeScript، وتجنّب `any`، وتحقّق من كل مدخل خارجي عبر Zod.
- يبقى كل تطبيق قابلًا للنشر باستقلال. الشيفرة المشتركة مكانها `packages/*`، ولا يستورد تطبيق تطبيقًا آخر.
- يجب أن يعمل كل تغيير يراه المستخدم بالعربية (من اليمين إلى اليسار) والفرنسية والإنجليزية، بشيفرة HTML دلالية ومتاحة للجميع.
- استخدم رموز التصميم بدل ألوان العلامة المكتوبة مباشرة.
- تحتفظ الصور العامة بمصدرها ونصّها البديل ونيّة القصّ. لا تُنشر صور غير مراجَعة أو مختلَقة.
- لا تُضِف أبدًا أسرارًا أو بيانات عملاء أو مخرجات بناء إلى المستودع.
